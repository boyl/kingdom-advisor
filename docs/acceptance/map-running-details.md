# 跑动地图与附近详情复查

问题：HUD 标签优先级受人物距离、手柄焦点影响，导致密集地图重复排布；同名地点按移动视窗的格子聚合，导致数量及代表地点跳变。
修正：标签采用静态优先级，聚合锚点绑定岛屿。附近模式仍正常跟随人物横向平移，焦点仍显示状态、描边和长按传送。

|---|---|---|
|M01|聚合格正负边界正确，类别优先级固定|test-map-layout.ps1 通过；属于模型自动测试|
|M02|既有密集避让、加载与换岛布局保持|既有地图测试通过|
|M03|附近建筑详情配置名称中英文明确|test-localization.ps1 通过；默认关闭沿用用户既有选择|

不以模型测试冒充跑动实机验收，不自动更新公开发布包。

实机发现并修正：selectedPayable 和最近交互搜索会命中 Player 1，导致玩家被误判为未知建筑。两条入口均排除 Player 组件；候选已编译，等待正常退出后安装及实机核验。无法移动问题仍待用户反馈，未标为通过。

新增验收：附近卡片应直接显示用途，无分页；没有 Payable 入口的城堡、城墙、塔楼、农舍仍参与 7 单位内最近建筑搜索，读取等级及状态，无付费入口时不调用 IsLocked，不显示虚假费用。中文、英文文案和构建通过；满级建筑真实存档核验仍未验证。

用户实机拒收：人物不在建筑前仍显示城墙。撤销原 7 单位搜索；全部入口采用 1.5 单位近距离门禁，游戏 selectedPayable 同样验证距离，离开清空，不沿用上次目标。test-target-proximity.ps1 先缺失契约失败再实现通过；实机到达/离开建筑仍未验证。

用户第二次实机拒收：站在弩炮改造塔下仍缺失。原生接口确认 Ballista 为 Workable 而非 Tower；改为缓存场景 WorkableBuilding、Ballista.tower、Baker，保留常规注册表，并按组件识别改造用途。缓存每2秒刷新，不逐帧全场景扫描。构建及安装通过；近距离出现、离开消失、弩炮识别三项实机仍未验证。
